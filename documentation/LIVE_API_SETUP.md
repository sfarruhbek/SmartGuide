# Рабочий frontend → API → Groq / Gemini

26 ноября 2026. Национальная форма теперь вызывает `POST /api/trips/generate`; `/khiva` вызывает `POST /api/roadmap/generate`; текст/фото гида — `/api/guide/ask`; озвучка генерируется сервером через Gemini. Карта по-прежнему использует авторский каталог и OpenStreetMap. Ключи находятся только на сервере.

## Текущий локальный запуск

- Приложение: `http://localhost:3000`.
- Настоящий API этой работы: `http://localhost:4001`.
- На 4000 ранее работал отдельный QA mock; он не является источником текущих планов и ответов. Его процесс не заменён.
- В игнорируемом `.env.ai.local` настроены ключи, `API_PORT=4001`, `AUTO_SEED=false`, `LANDMARK_STORE=json`.
- В `apps/tourist/.env.local`: `NEXT_PUBLIC_API_URL=http://localhost:4001`, `SMARTGUIDE_API_ORIGIN=http://127.0.0.1:4001`.
- Для dashboard в его `.env.local` используется `VITE_API_URL=http://localhost:4001`. Без PostgreSQL аналитика явно недоступна, вместо демонстрационных чисел.

В режиме `json` API читает существующие досье из файла, но действительно обращается к Groq/Gemini. Это не mock провайдеров. Данный режим не сохраняет взаимодействия в DB: `interactionId:0`, `analyticsAvailable:false`, `database:"not-used"`; analytics summary возвращает 503 `ANALYTICS_UNAVAILABLE`. Бэкендер затем подключает PostgreSQL, устанавливая `LANDMARK_STORE=postgres`, и проверяет сохранение событий. JSON-режим намеренно выбран явно, не является скрытой подменой неисправной базы.

## На другом компьютере

Скопировать `.env.example` в серверный `.env`, установить собственные действующие ключи и адреса. При стандартном `API_PORT=4000` frontend должен указывать тот же порт; примеры 4001 выше относятся к текущему компьютеру с занятым 4000. В режиме до настройки DB задать `LANDMARK_STORE=json`, `AUTO_SEED=false`.

```powershell
npm ci
npm run build:shared
npm run dev:api
# Во втором терминале:
npm run dev:tourist
```

Next проксирует `/api/*` на `SMARTGUIDE_API_ORIGIN`; это серверный URL. Для HTTPS использовать same-origin `/api` через Next/reverse proxy либо явно указать HTTPS API. Переменные `NEXT_PUBLIC_*` компилируются в браузерный bundle: после изменения URL требуется перезапуск dev или новая production-сборка. Ключи в них не помещать. Воспроизводимость оформления больше не зависит от Google Fonts: Inter/Playfair хранятся локально с OFL-лицензиями в `apps/tourist/src/app/fonts`.

## Поведение интерфейса

Пока запрос выполняется, кнопка и поля блокируются и показан статус ожидания. Клиент проверяет совпадение предпочтений, известные места, время и суммы. После ответа показывается источник AI либо явно обозначенный серверный базовый маршрут. При HTTP-ошибке остаются введённые значения и повтор; frontend не выдаёт мгновенную локальную генерацию за AI. Сохранённый серверный план восстанавливает тот же порядок мест и метаданные вместо повторного локального расчёта.

Деньги и время по-прежнему рассчитываются детерминированно сервером. Groq выбирает порядок известных мест; это не проверенные тарифы/расписания и не полное содержимое всех городов. Отзывы, публичные находки, платежи и DB-аналитика требуют дальнейшей работы.

## Результат проверки слияния сениора

Коммит `c2ee4a6` содержит всю ветку `17cade6`; код `apps/**` и `packages/**` относительно неё не изменён. Новые `BUSINESS_MODEL.md`, `SMETA_BUDGET.md`, `ROADMAP.md` из `main` сохранены. Это проверка сохранности изменений, а не подтверждение готовности всех описанных там функций.

Остаётся рассинхронизация: новая бизнес-модель описывает Trip Pass $4.99/$12.99, но legacy dashboard-калькулятор и API revenue пока считают $4 и долю музея 30%. Эта итерация подключения AI не объявляет старый калькулятор новой экономикой; backend/frontend должны согласовать новый revenue-контракт отдельно. Обновлённая смета сама по себе не реализует биллинг.
