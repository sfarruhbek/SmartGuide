# SmartGuide: аудит фронтенда и готовности к хакатону

Дата: 26 ноября 2026, Asia/Tashkent. Ветка: `feat/uzbekistan-solo-travel`.

Актуализация после AI-интеграции: в `feat/ai-provider-routing`, коммит `66d53ca`, добавлены Groq planner/guide/vision и Gemini speech. Реальные запросы плана и озвучки через HTTP, сервисы ответа и фото проверены; национальный frontend всё ещё локальный, полный guide HTTP + PostgreSQL и публичный HTTPS-стенд не подтверждены. Исторические UI-проверки ниже относятся к frontend-аудиту. Следующая работа с владельцами и критериями: [BACKEND_TASKS.md](BACKEND_TASKS.md); техническая передача: [AI_BACKEND_HANDOFF.md](AI_BACKEND_HANDOFF.md).

## Вердикт по 50 млн

Сейчас это демонстрируемый MVP с понятной идеей, но оснований уверенно обещать первое место нет. Фронтенд можно довести до аккуратного, устойчивого демо. Победу сильнее ограничивают полнота продукта, реальные данные, подтверждение спроса и соответствие выбранному треку.

[Официальная страница хакатона](https://hackathon.uzbektourism.uz/) подтверждает 50 млн сумов за первое место в каждом из трёх треков и формат финала 3 минуты + 2 минуты вопросов. Публичную шкалу с весами критериев на этой странице не нашёл. Ниже — моя инженерная и продуктовая оценка, не оценочный лист жюри и не вероятность победы.

По описанию пользовательского сценария продукт ближе к персонализации путешествий. Если команда уже заявлена в треке цифровизации малого турбизнеса, в питче нужен убедительный результат для локального партнёра: контент, распространение, реальные обращения туристов и польза панели. Автоматически менять зарегистрированный трек или подменять основную идею B2B-презентацией не нужно.

## Найдено и исправлено во фронтенде

| Приоритет | Проблема | Изменение |
| --- | --- | --- |
| P1 | `overflow-x:hidden` одновременно на html/body создавал дополнительные scroll-контейнеры | Один основной скролл документа; ограничения ширины у grid/flex и перенос длинного текста |
| P1 | На телефоне дни поездки уходили в горизонтальную ленту с полосой прокрутки | Выбор дня через select и предыдущий/следующий день; на широком экране кнопки переносятся |
| P1 | Нижняя навигация: подписи 9px, неравномерные кнопки, отступ учитывался только в футере | Три равные кнопки, короткие подписи, явное активное состояние, резерв высоты у страницы и safe-area |
| P1 | Поля 14px могли вызывать автоматический зум на iPhone | Поля ввода 16px; улучшен размер основного текста и кликабельных элементов |
| P1 | Открытая карта / день / место сбрасывались после refresh; Back не переключал раздел | Проверяемое состояние в URL, поддержка истории, восстановление дня и выбранной карточки |
| P1 | AI fetch мог бесконечно держать интерфейс занятым | Тайм-аут 45 сек, отмена при уходе/смене языка, проверка основного response shape |
| P1 | Ошибка SSR/API давала системный экран; неизвестная ссылка — стандартный Next 404 | Собственные локализованные страницы с повтором и возвратом к карте |
| P1 | На HTTP в локальной сети `crypto.randomUUID()` мог отсутствовать | Совместимый генератор локальных ID; стабильная сессия при недоступном storage |
| P1 | Недоступный endpoint отзывов предлагал повторять заведомо неработающую отправку | Для 404/405/501 показана недоступность; успешное сохранение не имитируется |
| P1 | Карта перехватывала вертикальный жест страницы | Обычная прокрутка страницы; отдельный режим перемещения карты, сброс к городу |
| P1 | В обработчике drag использовался ref после потенциального pointerup | Снимок координат захватывается до обновления state |
| P1 | При 50 находках старый черновик удалялся молча; пробельные поля не объясняли отказ | Лимит сообщает о себе, старые записи сохраняются, ошибки заполнения видны, после успешного добавления форма очищается |
| P1 | Формулы в вопросах могли исполняться при открытии CSV в таблице | Экранирование формул в локальном и серверном CSV, тест кавычек/переносов/BOM |
| P1 | На HTTPS стандартный localhost API превращался в HTTP-запрос на публичный хост | Для этой конфигурации используется same-origin API через reverse proxy; явные URL сохраняются |
| P2 | Смета не давала быстрого понимания структуры расходов | Разбивка: еда, транспорт, билеты, проживание, резерв |
| P2 | Локально сохранённую поездку нельзя было унести с собой | Скачивание текстового плана со всеми днями, расходами, источниками и пометками об оценочных ценах |
| P2 | Стили текстовых полей затрагивали file/range и аудиоплеер | Ограничены нужными типами полей; скрытый file input остаётся 1px |

Вертикальная прокрутка длинной страницы нужна. Горизонтальная прокрутка всего экрана, срезанный текст и перекрытые панелью последние элементы — ошибки. Внутренняя карта может перемещаться, а историческая навигация Xiva остаётся отдельным компонентом.

## Чего ещё не хватает продукту

| Срочность | Пробел | Факт в текущем проекте | Кто доводит |
| --- | --- | --- | --- |
| P0 до питча | Настоящий сквозной сценарий | AI-сервисы и HTTP plan/speech проверены в последующей ветке; национальный UI ещё локальный, полный guide + DB + HTTPS на телефоне не принят. Локальный 4000 в UI-аудите был QA mock | Backend B01–B04 + Frontend F01 из списка задач |
| P0 до питча | Подтверждённая локальная ценность | В каталоге 15 мест в четырёх городах; ссылки публичные. Эксклюзивный архив и проверка местными экспертами не доказаны | Контент/AI + PM |
| P0 до питча | Реальная валидация | В репозитории нет проверяемого списка проведённых интервью, результатов задач и договорённостей | PM/вся команда |
| P0 до питча | Честное демо географии | Планировщик предлагает города страны, AI-контент подключён к пяти обидам Хивы; общенационального распознавания нет | Backend/AI + сценарий питча |
| P1 | Конкретные заведения и актуальные тарифы | Еда — временные и денежные allowance, а не проверенные кафе; цены билетов/такси оценочные | Данные/партнёры + Backend |
| P1 | План с датами и реальными ограничениями | Нет календаря, часов работы, выходных, мест в поезде, фактической длительности переезда | Backend/данные, затем frontend |
| P1 | Общественная карта находок | Есть только личные черновики на устройстве; нет публикации, проверки и модерации | Backend/контент, затем frontend |
| P1 | Настоящий feedback loop | В текущих backend routes нет roadmap/feedback/nearby/visit/export; optional insights не доказывают работающий цикл | Backend/AI |
| P1 | Коммерческая проверка | $4, 70/30, SaaS — гипотезы; нет payment ledger, подтверждённых продаж и партнёрских договоров | PM/Backend |
| P2 | Полностью локализованный контент | UI на шести языках, новые истории в основном EN/RU/UZ; остальные языки честно получают English fallback | Контент/переводчики |
| P2 | Полноценный offline | Есть локальная поездка и текстовый экспорт; offline-карт и service worker нет | Отдельный этап frontend |
| P2 | Происхождение старых фото Хивы | Для новых city WebP есть credits; права/источник старых пяти фото не описаны | Контент/владелец материалов |

Это список незакрытых возможностей, не утверждение, что весь MVP обязан стать production-системой до финала. Для победной демонстрации важнее один проверенный полезный сценарий, чем много экранов с имитацией данных.

## Что сделать команде до выхода

1. Выбрать один реальный сценарий и пользователя. Показать бюджет и дни, объяснить пользу скрытого места, открыть источник, получить один настоящий AI-ответ. Разницу между национальной концепцией и пилотом назвать прямо.
2. Подключить и прогнать настоящий backend/DB/AI на том HTTPS-адресе, который будет в QR. Проверить на телефоне через мобильную сеть. Не засчитывать mock как проверку интеграции.
3. Провести короткие наблюдаемые проверки с целевыми путешественниками и местным экспертом. Несколько интервью дадут качественные сигналы, но не статистическую валидацию рынка. Сохранить реальные ответы и согласие на демонстрацию.
4. Для выбранного маршрута подтвердить хотя бы небольшой набор мест, порядок, часы работы и цены с датой проверки. Для легенд указывать именно статус предания.
5. Согласовать с одним локальным партнёром конкретный следующий шаг пилота. Показывать статус переговоров, а не называть потенциальную организацию клиентом.
6. Подготовить трёхминутный питч и резервное видео. На вопросы «почему не обычный AI/карта?», «кто платит?», «что уже работает?» отвечать проверяемыми фактами.

## Проверки после исправлений

- 16 автоматических тестов: бюджет/время/переезды, USD и миграция, карта и фильтры, URL, текстовый экспорт, тайм-аут/отмена, некорректные API-ответы, приватное хранилище, финансовая модель и CSV.
- В браузере проверены plan / itinerary / map на ширинах 320, 375, 390, 700, 701, 768, 1280 и 1920 px. В 24 сочетаниях ширины и раздела ширина документа совпала с доступной шириной viewport; выходящих за экран обычных элементов не найдено. На телефонах три кнопки нижней навигации равной ширины, высота панели 76 px без аппаратного safe-area.
- Проверены шесть языков на узкой ширине, 14-дневная поездка и длинное название города, восстановление выбранного дня после refresh, Back/Forward, фильтр и выбранная карточка карты.
- Скачан и прочитан `smartguide-trip-ru.txt`: все дни, категории расходов, суммы и ссылки на источники присутствуют. Проверены ошибка пробельного названия находки, создание/удаление тестового черновика и очистка формы.
- Проверка AI-страницы на 320 px проводилась до последних изменений обработки запросов. После продолжения чата браузерный доступ стал недоступен: заключительная UI-проверка ответа AI, новой страницы 404 и dashboard в этой итерации не выполнена. Их программные проверки и сборка проходят; это ограничение проверки, а не подтверждённая работоспособность на устройстве.
- Настоящие Safari/Android, экранная клавиатура, вырезы экрана и публичный HTTPS backend требуют проверки на целевых устройствах. Локальный API остаётся QA mock.

## Границы ответственности

В исходном frontend-аудите изменялись `apps/tourist`, `apps/dashboard` и документация. Последующая отдельная AI-задача по запросу владельца расширила backend и shared `sourceMode`; DB-схема не менялась. Оставшиеся задачи Backend, Frontend, AI/контента и PM отдельно перечислены в [BACKEND_TASKS.md](BACKEND_TASKS.md).

Автотесты и build проверяют программные контракты. Они не доказывают историческую точность, прибыльность, качество AI или соответствие неизвестной шкале жюри. Проверки viewport в desktop-браузере не заменяют аппаратную проверку Safari/Android, экранной клавиатуры и safe-area.
