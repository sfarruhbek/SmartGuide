## Конфигурация и запуск

Секреты читаются только сервером: переменные окружения процесса имеют приоритет, затем корневой `.env.ai.local`, корневой `.env`, `apps/api/.env` (без перезаписи уже заданных значений). `.env.ai.local` игнорируется Git. Не добавлять ключи в `NEXT_PUBLIC_*`, `VITE_*`, клиентские файлы, логи или JSON-отчёты. Ключи из переписки следует отозвать и заменить; в репозитории только шаблоны.

```dotenv
GROQ_API_KEYS=replace_with_server_keys_separated_by_commas
GROQ_MODELS=openai/gpt-oss-120b,openai/gpt-oss-20b,qwen/qwen3.8-27b
GROQ_VISION_MODEL=qwen/qwen3.8-27b
GEMINI_API_KEY=replace_with_server_key
GEMINI_TTS_MODEL=gemini-3.8-flash-lite-tts
GEMINI_TTS_FALLBACK_MODELS=gemini-3.8-flash-tts,gemini-3.1-flash-tts-preview,gemini-2.5-flash-preview-tts
GEMINI_TTS_VOICE=Sulafat
```

Из корня репозитория:

```powershell
npm run build:shared
npm run ai:check --workspace=@smartguide/api
npm run ai:check --workspace=@smartguide/api -- --probe
npm run test --workspace=@smartguide/api
npm run ai:smoke --workspace=@smartguide/api
npm run dev:api
```

`ai:check` читает каталоги и проверяет импорт; `--probe` дополнительно расходует небольшую квоту на генерацию с каждого ключа и запросы текста/речи через рабочую цепочку. `ai:smoke` делает реальные платные запросы на временном локальном порту, не заменяя уже запущенный API. Стандартный dev API использует `API_PORT`, по умолчанию 4000.

## HTTP-контракт

`POST /api/trips/generate` принимает тот же ввод, что текущий национальный UI:

```json
{"cities":["khiva","bukhara"],"days":4,"budget":200,"interests":["local","history"],"accommodation":true,"customCity":""}
```

`budget` — доллары, максимум два знака после запятой; рассчитанные суммы в `trip` — целые центы USD. Дни 1–14, бюджет >0 и ≤1 млн долларов, интересы `history | local | food | nature | sacred`. ID городов берутся из каталога, число выбранных направлений не превышает дни. Пустой список разрешён только с `customCity`. Неизвестный ID, лишнее поле или неправильный бюджет → 400 без обращения к провайдерам.

Ответ: `{trip, source, modelUsed, fallbackReason, costBasis, amounts, warnings}`. `trip` соответствует текущему `Trip` v2: `currency`, `input`, `days`, `subtotal`, `reserve`, `total`, `shortfall`, `createdAt`. `source` — `groq | local-fallback`; `fallbackReason` — `null | no-catalog-places | not-configured | exhausted | deadline | provider-error`. Если AI недоступен, HTTP 200 содержит честно обозначенный локальный план. `warnings` пока англоязычные технические сообщения; frontend должен локализовать их перед отображением.

Модель возвращает только упорядоченные ID известных мест. Zod и дополнительные проверки запрещают неизвестные ID, дубли, добавленные цены и сломанный JSON. Время и деньги рассчитываются сервером: еда, посещения, транспорт, n−1 ночей, 10% резерв и явный дефицит. Алгоритм не гарантирует, что любой бюджет достаточен. Это смета и временные блоки, не доступность, бронирование или проверенный транспортный маршрут. Дата поездки, ресторанные адреса и реальные расписания пока не реализованы.

В каталоге 16 городов и 15 мест четырёх городов. Для остальных — явные блоки самостоятельного исследования и предупреждение. Снимок `apps/api/data/planner-catalog.json` обновляется из авторского frontend-каталога командой `npm run catalog:sync --workspace=@smartguide/api`. После обновления запускать тесты; алгоритмы планирования пока остаются в двух приложениях, изменения расчётов синхронизировать.

`POST /api/audio/speech`: `{text, language}`; текст 1–1400 символов, язык `en | ru | uz | es | ja | ko`. Успех: `{audioBase64, audioMimeType:"audio/wav", modelUsed, provider:"gemini"}`. Все TTS недоступны → 503 `{code:"AUDIO_UNAVAILABLE", error, text}`, `Retry-After: 60`. Клиент сохраняет текст и может предложить браузерную озвучку. PCM 16-bit little-endian 24 kHz конвертируется в RIFF/WAV; готовый WAV проверяется и сохраняется.

`POST /api/guide/ask` сохраняет существующую форму. Новый `sourceMode: groq-rag`; историческое `gemini-rag` остаётся в shared union для совместимости со старыми ответами/аналитикой. В этом legacy endpoint Gemini отвечает за TTS, Groq — за текст и фото. Фото без уверенного совпадения и без выбранного slug → 422; с выбранным slug ответ относится к нему, `identifiedByVision:false`. Его пять slug не ограничивают отдельный национальный Live-popup. Ни один режим не подтверждает исторические сведения самим фактом распознавания фото.

`GET /api/health` сообщает конфигурацию провайдеров и кандидаты моделей, но не проверяет ключи онлайн. В режиме `postgres` недоступная DB даёт 503. В явно выбранном `json` API работает без DB: HTTP 200, `database:not-used`, `analyticsAvailable:false`; analytics summary недоступен с 503.

## Переключение и квоты

- Ключи выбираются по очереди; 401/403 исключают credential до перезапуска. Строгое ограничение: максимум 8 попыток, по 10 секунд на запрос, общий бюджет одной операции 25 секунд (настраивается).
- 429 ставит модель на паузу для всех ключей этого процесса. Учитываются `Retry-After` и Groq reset headers, иначе 60 секунд. Следующая попытка идёт к следующей модели. Ошибка общей billing-квоты приостанавливает весь пул.
- 404, 400, 5xx и испорченный ответ переключают модель с короткой паузой; сетевой сбой временно исключает ключ. Ответы провайдера и ключи не пишутся в логи и не возвращаются клиенту.
- Входные AI-маршруты ограничены 20 запросами в минуту на IP и 4 одновременными запросами на процесс. Лимиты настраиваются через `AI_REQUESTS_PER_MINUTE` и `AI_MAX_CONCURRENT`.
- Состояние квот и ограничений хранится в памяти. Для нескольких инстансов нужны общий store, пользовательская авторизация/квоты и правильная настройка доверенного reverse proxy. В текущем Express `trust proxy` не включён: за прокси IP-лимит может быть общим.

Согласно [документации Groq](https://console.groq.com/docs/rate-limits), лимиты действуют на организацию. Четыре ключа одной организации не дают четырёхкратную квоту. Для разных организаций/проектов следует явно реализовать отдельные пулы; текущая конфигурация консервативно считает все ключи общим пулом. Поддержка фото Qwen: [Groq vision](https://console.groq.com/docs/vision). Формат PCM и TTS: [Gemini speech generation](https://ai.google.dev/gemini-api/docs/speech-generation).

## Присланный JSON

Оригинал сохранён без изменений в `apps/api/data/imports/ichan_qala_5_obida.json`. `content-import.ts` валидирует структуру и готовит сводку для ревью. Данные пока не загружаются в рабочее RAG-досье или БД автоматически:

- Калта-Минор: 1852–1855 в новом файле против 1851–1855 в старом.
- Джума-мечеть: 212 колонн против 213.
- `tosh-hovli-palace` сопоставлен с прежним `tosh-hovli`; `islam-khoja-minaret` — новый ID. Отсутствие Пахлавана Махмуда в импорте не удаляет существующий объект.
- Истории смешивают исторические утверждения и легенды. Нужны ссылки к конкретным утверждениям и маркировка устных преданий.
- Общая страница UNESCO, строка «архив / UNESCO» и главная музея не подтверждают каждое утверждение. Wikimedia File URLs — страницы источников, а не готовые ссылки на изображения.

После исторического ревью backend-владелец может утвердить записи и спроектировать миграцию. Это не препятствует использованию текущего каталога для тестов API.
